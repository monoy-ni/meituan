# 主题出游局设计器说明文档

## 1. Skill 是做什么的

`themed-outing-designer` 是一个把“普通出门安排”升级成“有主题感的完整体验”的 Skill。

它不是简单给用户列一个“先去哪、再去哪、最后吃什么”的攻略，而是把一次朋友局、城市游玩、下班局、周末局，包装成一个更有记忆点的主题活动，例如：

- 下班回血局
- 多巴胺补给局
- 出片局
- 松弛聊天局
- 破冰社交局
- 低成本快乐局
- 城市副本局
- 发疯解压局
- 早睡养生局
- 友情充电局

这个 Skill 的核心价值是：给一次出行补上“主题、剧情、玩法、情绪价值、互动设计和收尾仪式”，让活动更像一个可参与、可传播、可复用的“局”。

## 2. 适用场景

当用户有以下诉求时，适合使用这个 Skill：

- 想把普通聚会设计得更有意思
- 想做一套有主题的朋友出游方案
- 想把“吃饭 + 玩 + 逛”包装成完整玩法
- 想给社群活动、同城局、轻社交局做体验设计
- 想让一条路线更有剧情感、任务感和参与感

典型输入示例：

- “帮我设计一个下班回血局，在滨江，吃火锅再唱 K。”
- “我想去西湖玩，但希望像体验小青和许仙故事一样有主题。”
- “设计一个多巴胺补给局，地点是商场，包含拍照、甜品、逛店。”
- “给我做一个城市副本局，路线是咖啡馆 → 展览 → 夜宵。”

## 3. 不适用场景

以下情况不建议直接用这个 Skill 输出完整方案：

- 用户只想要普通旅游攻略或景点清单
- 用户只想查餐厅、景点、营业时间等事实信息
- 严肃商务活动、培训课程、正式团建方案
- 涉及高风险、违法、扰民、强制社交或隐私暴露的活动

如果用户只是要“信息查询”，应该优先用检索或攻略类能力；如果用户要的是“玩法包装和体验设计”，才适合用这个 Skill。

## 4. 这个 Skill 的输入是什么

### 必填信息

至少应拿到两个关键信息：

1. 主题
2. 地点或区域

例如：

- 主题：下班回血局 / 出片局 / 城市副本局
- 地点：西湖 / 滨江 / 某商场 / 某条街区

### 建议信息

如果用户愿意提供，方案质量会更高：

- 活动链路：例如“桌游 → 火锅 → KTV”
- 参与人数与关系：朋友、同事、情侣、陌生人等
- 时间段与总时长：下班后 3 小时、周末半天、一天
- 预算范围：低成本、人均 100、人均 300
- 氛围偏好：治愈、热闹、搞笑、复古、浪漫、电影感
- 限制条件：不喝酒、不暴晒、不剧烈运动、有人社恐、有人会迟到

### 信息不足时的处理规则

如果缺少“主题”或“地点”，不要直接硬写完整方案，应该先追问。

推荐追问方式：

> 可以，我先补两个关键信息：这次想做成什么主题的局？大概在哪个地点或区域玩？

如果缺少人数、预算、时长等次级信息，可以带着默认假设先出方案，但必须在开头说明假设条件。

## 5. 输出内容包括什么

这个 Skill 的标准输出不是一段随意描述，而是一套结构化活动方案。核心模块包括：

### 1. 局名

- 给 1 个主局名
- 再给 2 到 3 个备选局名

要求：

- 像活动标题
- 适合发群公告
- 有传播感和记忆点

### 2. 一句话体验设定

用一句有画面感的话，说明这次局的体验是什么。

示例风格：

> 今晚不做打工人，我们去城市里捡回一点电量。

### 3. 适合人群与默认假设

需要明确：

- 适合几个人
- 什么关系类型
- 预计时长
- 默认预算

如果用户没有说清楚，必须写出“以下按 4 人、3 小时、人均 150 元设计”这种假设说明。

### 4. 整体玩法主线

先讲清楚这次局是怎么“玩”的，而不是一上来就列清单。

### 5. 分阶段流程

按时间线拆成若干阶段，通常包括：

- 时间
- 地点/环节
- 体验目标
- 玩法任务
- 互动问题或话术
- 拍照/记录点

### 6. 任务卡/互动卡

至少设计 5 张任务卡，要求：

- 轻量
- 好执行
- 不尴尬
- 不需要强表演

### 7. 餐饮/娱乐包装方式

不是只说“去吃火锅”，而是解释这个环节在主题里的作用。

例如：

- 火锅是“回血补给站”
- KTV 是“情绪释放点”
- 咖啡馆是“开场缓冲区”

### 8. 发起人/主持人话术

给出可以直接复制的：

- 开场话术
- 转场话术
- 收尾话术

### 9. 预算与降级方案

要考虑实际执行中的问题：

- 预算超支怎么办
- 下雨怎么办
- 有人迟到怎么办
- 店满了怎么办
- 人少了怎么办

### 10. 朋友圈/群公告文案

输出一段适合发群或朋友圈的短文案，通常控制在 80 到 150 字。

## 6. 这个 Skill 的设计思路

这个 Skill 背后不是“路线拼接”，而是“主题体验设计”。

它主要遵循以下原则：

### 1. 主题先行

主题不是装饰，而是要影响整套方案：

- 局名
- 世界观设定
- 任务设计
- 打卡方式
- 餐饮选择理由
- 收尾仪式

### 2. 体验感强于攻略感

输出重点不是“去哪”，而是“为什么去、去了做什么、有什么情绪价值”。

### 3. 游戏化但不幼稚

允许使用：

- 任务卡
- 抽签
- 城市副本
- 积分
- 盲盒
- 挑战机制

但整体要轻巧自然，不能像培训破冰游戏。

### 4. 低压力社交

尤其在破冰社交局、友情充电局、松弛聊天局中，要避免：

- 强制分享隐私
- 强制表演
- 情感逼问
- 公开让人下不来台的互动

### 5. 方案必须可落地

输出要能直接执行，因此必须兼顾：

- 时间节奏
- 路线顺序
- 预算控制
- 替代方案
- 主持话术

## 7. 当前内置主题能力

根据 `SKILL.md`，这个 Skill 已经内置了多种主题理解，常见包括：

| 主题 | 关键词 | 典型体验主线 |
| --- | --- | --- |
| 下班回血局 | 松弛、热食、低脑力、被照顾感 | 从工位残血到人类满电 |
| 多巴胺补给局 | 彩色、甜、拍照、即时快乐 | 收集快乐颜色，给情绪充电 |
| 出片局 | 镜头、造型、氛围感、街拍 | 完成一组人生电影剧照 |
| 松弛聊天局 | 慢、舒服、真诚、长谈 | 把话慢慢说完，把心慢慢放下 |
| 破冰社交局 | 低压力认识、随机连接、自然组队 | 像玩游戏一样认识新朋友 |
| 低成本快乐局 | 少花钱、小确幸、城市免费资源 | 用很少的钱买到很大的快乐 |
| 城市副本局 | 地图、关卡、任务、通关 | 把城市当成开放世界游戏 |
| 发疯解压局 | 释放、唱出来、动起来、搞笑 | 合法发疯，快乐重启 |
| 早睡养生局 | 温和、早结束、放松、修复 | 把夜晚还给身体 |
| 友情充电局 | 陪伴、默契、回忆、表达感谢 | 给友情续航 |

这意味着它不是纯自由发挥，而是有一套预设的主题语义和体验方向作为支撑。

## 8. 文件结构说明

当前目录结构如下：

```text
themed-outing-designer/
├─ SKILL.md
└─ references/
   ├─ output-template.md
   └─ theme-dictionary.md
```

### `SKILL.md`

这是主规范文件，定义了：

- Skill 名称
- 适用与不适用场景
- 输入要求
- 信息不足时的追问规则
- 设计原则
- 输出格式
- 风格要求
- 安全边界

### `references/theme-dictionary.md`

这是主题词典，主要帮助 Skill 理解不同主题的气质、关键词和适合的玩法方向。

### `references/output-template.md`

这是输出模板，主要用于约束最终产出的结构，让结果更稳定、更完整。

## 9. 这个 Skill 适合谁用

这个 Skill 适合：

- 想做朋友局、社群局、同城局的人
- 想把普通路线包装成更有体验感的人
- 想做活动策划但不想只写流程表的人
- 想为城市游玩增加主题叙事和互动玩法的人

尤其适合“年轻人情绪价值 + 轻社交 + 城市体验”这类方向的活动设计。

## 10. 使用时的注意事项

### 不要做的事

- 不要把它当成普通攻略生成器
- 不要只输出地点清单
- 不要用很空的形容词堆满全文
- 不要设计危险、违法、扰民、过量饮酒的玩法
- 不要用高压社交任务逼用户参与

### 建议做的事

- 先确认主题和地点
- 不足信息时轻量追问
- 把活动写成“体验主线 + 分阶段玩法”
- 给出能直接复制使用的话术
- 提供降级方案，保证落地性

## 11. 一句话总结

`themed-outing-designer` 不是帮用户“排一个行程”，而是帮用户把一次普通出门设计成一个有主题、有玩法、有互动、有记忆点、还能真正落地执行的“局”。
